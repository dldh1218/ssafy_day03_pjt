01. 프로젝트 정의LOCALHUB · FUNCTIONAL SPECIFICATION

서울을 고르고, 발견하고, 이야기하는 흐름

LocalHub는 공공 관광 데이터를 표준 형태로 정규화하여 서울 25개 자치구의 장소를 지도와 카테고리로 탐색하게 하고, 장소 단위 커뮤니티와 AI 추천 경험을 제공하는 반응형 SPA(Single Page Application)다.

25서울 자치구
7장소 카테고리
6,518배포 데이터 레코드
2핵심 화면

목표와 사용자 가치

목표사용자 가치성공 기준
지역 탐색 단순화서울 지도를 직접 선택하거나 검색어로 원하는 자치구·장소에 빠르게 진입홈 → 탐색 화면 진입이 2회 이내 상호작용으로 가능
정보 탐색 효율 향상카테고리, 자치구, 검색어를 결합해 대량 데이터를 좁혀 확인필터 변경 즉시 목록·지도 마커가 함께 갱신
장소 중심 참여방문 후기, 댓글, 좋아요로 장소별 경험을 축적게시글 CRUD, 댓글 등록/삭제, 조회·좋아요 정상 동작
맞춤 추천 보조자연어 질문으로 보유 데이터 범위 안에서 장소 추천을 획득지역/카테고리 문맥을 포함한 AI 답변 또는 명확한 오류 안내

주요 사용자

  • 서울 방문 전 후보 장소를 찾는 여행자
  • 주말 활동·문화 공간을 찾는 서울 생활자
  • 방문 경험을 공유하고 싶은 커뮤니티 참여자

범위

  • 서울 지역 및 7개 관광 카테고리
  • 브라우저 기반 데이터 조회와 로컬 커뮤니티
  • OpenAI API 기반 여행 도우미
범위 제외: 회원가입/로그인, 서버 DB, 결제, 예약, 관리자 페이지, 실시간 동기화, 음식점 카테고리는 현 버전에 포함되지 않는다.

공통 예외 처리

  • 검색 결과가 없으면 빈 결과 상태를 노출하고 기존 지도 오류를 발생시키지 않는다.
  • 이미지가 없는 장소는 카테고리 아이콘 또는 대체 UI를 사용한다.
  • 좌표가 없거나 서울 범위를 벗어난 데이터는 목록에는 유지할 수 있으나 지도 마커에서는 제외한다.
  • 쿼리 문자열과 경로의 한글은 URI 인코딩/디코딩하여 새로고침 후에도 상태를 복원한다.

F-18AI 오류/이력P2API 키 누락, 401, 429, 네트워크 오류상황별 친화적 메시지 및 대화 이력 저장패널 재개 시 이력 복원, 실패가 화면 전체를 중단하지 않음

비즈니스 규칙

커뮤니티

  • 게시글과 댓글은 익명 기반이며 비밀번호가 소유권 검증 수단이다.
  • 첨부 이미지는 브라우저에서 축소·인코딩한 문자열로 저장한다.
  • 랭킹은 게시글, 댓글, 최근 7일 활동 가중치를 사용한다.
  • 샘플 게시글은 장소 데이터 중 최대 25개를 무작위로 선택한다.

AI 도우미

  • 데이터에 없는 장소/일정 정보를 만들어내지 않도록 시스템 지침을 부여한다.
  • 음식점 데이터는 제공하지 않는다고 명시한다.
  • 정확한 날짜·일정이 없으면 모른다고 안내한다.
  • API 응답은 참고 정보이며 최신성 차이가 있을 수 있음을 표시한다.
보안 중요: 비밀번호는 현재 평문으로 localStorage에 저장된다. 데모 외 용도에서는 인증 서버, 해시 저장, 입력 길이 제한, XSS 방어, 콘텐츠 신고/관리 기능이 선행되어야 한다.

Definition of Done

  • 명세된 정상/빈 결과/오류 흐름이 모두 동작한다.
  • 직접 URL 진입 및 새로고침이 정상이다.
  • 필터·목록·지도·상세 선택 상태가 일치한다.
  • 게시글/댓글 비밀번호 검증이 우회되지 않는다.
  • 모바일 핵심 동선에서 가로 스크롤이 없다.
  • API 키 누락 시 명확한 안내를 제공한다.
  • production build가 성공한다.
  • 치명적 콘솔 오류와 깨진 링크가 없다.
  • 데이터 출처와 AI 한계 문구가 노출된다.
  • 회귀 테스트 결과와 알려진 제약을 기록한다.
우선순위 정의: P1은 핵심 사용자 여정을 성립시키는 필수 기능, P2는 발견성과 참여 경험을 높이는 중요 기능이다. 현 소스 기준 F-01~F-18은 구현 상태이며, 운영 수준의 서버·보안 전환은 별도 후속 범위다.
